## 4. Detail temuan

### H1 — Tidak ada jalur "ajukan sesi tambahan" saat punya jadwal aktif

`components/patient/patient-therapy-calendar.tsx:132`

```ts
const showAvailability = reschedulingAppointment !== null || !hasActiveSchedule;
```

Efeknya:
- Sel kalender tidak menandai hari yang punya slot (semua tanggal polos).
- Klik tanggal tanpa sesi → drawer hanya "Tidak ada sesi pada tanggal ini." + tombol "Batal" (dead end).
- Subtitle halaman tetap menjanjikan "…atau mengajukan jadwal baru."
- Pasien yang butuh 2×/minggu tidak punya jalan sama sekali; satu-satunya jalur adalah **mengubah** jadwal yang ada.

Rekomendasi: pisahkan "lihat sesi" dan "cari slot". Saat punya jadwal aktif, tetap tampilkan slot tersedia dengan CTA **"Ajukan Sesi Tambahan"**, atau minimal tampilkan link "Ingin menambah sesi? Hubungi tim Hafta" yang bisa diklik.

### H2 — Status pengajuan ubah jadwal tidak terbaca

- Drawer tanggal tujuan (11 Nov) menampilkan **"Tidak ada sesi pada tanggal ini."** padahal sel tanggalnya berlabel "Menunggu ACC".
- Drawer tanggal asal (4 Nov) **tidak** menandai bahwa sesi ini sedang diajukan pindah.
- Chip "Menunggu ACC Terapis — Diajukan pindah ke …" ada di kode (`patient-therapy-calendar.tsx:483-495`) tetapi berada di dalam cabang "ada appointment" dan di-key berdasarkan `requestedDate`, sehingga praktis tidak pernah muncul pada kasus normal.

Rekomendasi: render blok "Pengajuan perubahan jadwal" **independen** dari ada/tidaknya sesi di tanggal itu, isi: jadwal asal → jadwal usulan, status, dan tombol **Batalkan Pengajuan** (server action sudah tersedia).

### H3 — Risiko pindah fisioterapis tanpa peringatan

- Sesi aktif: **Dewi Lestari**. Slot yang ditawarkan: **Hafta Terapis 1**.
- `server/actions/appointment-requests.ts:215+` tidak mewajibkan `therapistId` sama dengan appointment asal (malah menyimpan `previousTherapistId`).
- UI hanya menampilkan baris kecil "Fisioterapis: …" tanpa menyatakan "akan berubah dari X ke Y".
- Jika beberapa terapis punya slot di jam yang sama, terapis dipilih otomatis `slots[0]` (`patient-therapy-calendar.tsx:515`) — pasien tidak bisa memilih.

Rekomendasi: tampilkan peringatan eksplisit + konfirmasi bila terapis berubah, dan/atau batasi slot ke terapis penanggung jawab kecuali pasien memilih "ganti terapis".

### H4 — Guard pengajuan ganda hanya di server

UI membiarkan alur penuh (pilih tanggal → pilih jam → submit) lalu menampilkan error: *"Anda sudah memiliki pengajuan perubahan jadwal yang sedang menunggu konfirmasi dari terapis."*

Rekomendasi: saat `pending` ada, ganti tombol "Ubah Jadwal" menjadi state non-aktif dengan penjelasan, dan tampilkan banner "Pengajuan sedang ditinjau — [Batalkan]".

### M1 — Copy salah konteks saat mengubah jadwal

`patient-therapy-calendar.tsx:503` hardcoded: *"Pilih slot waktu di bawah untuk mengajukan jadwal baru."* Saat mode ubah jadwal seharusnya: *"Pilih slot untuk memindahkan sesi Anda."*

### M2 — Kartu ringkasan tidak informatif saat pending

Kartu atas hanya berubah badge → "Menunggu konfirmasi" + CTA "Lihat Detail", tetapi masih menampilkan jadwal lama. Pasien tidak bisa memverifikasi "saya mengajukan pindah ke mana?" tanpa membuka kalender.

### M3 — Legenda kalender

Legenda memuat "Slot tersedia" (swatch kuning) dan "Ada slot kosong" (dot hijau) — dua entri untuk satu konsep. "Menunggu ACC" hanya muncul bila ada pengajuan, "Sesi Anda" dan "Hari Libur/Minggu" selalu ada. Saat mode normal dengan jadwal aktif, legenda hanya berisi 2 entri sehingga status lain tidak terjelaskan.

Rekomendasi: satu entri per status, selalu tampil, dengan contoh bentuk (dot/ring/isi) yang benar-benar dipakai sel.

### M4 — Tap target (mobile)

| Elemen | Ukuran | Catatan |
|---|---|---|
| Link "Semua" (Rekam Medis) | 58×16 | **Gagal WCAG 2.5.8** (min 24×24) |
| Tombol bulan sebelumnya/berikutnya | 32×32 | di bawah 44px HIG |
| Hamburger & "Tutup menu" | 28×28 | di bawah 44px |
| Link sidebar | 228×38 | di bawah 44px |
| Tombol "Lihat Detail"/"Isi Form Awal" | tinggi 35px | di bawah 44px |

### M5 — Navigasi waktu

Tidak ada tombol "Hari ini", tidak ada date picker, tidak ada shortcut "bulan ini". Mencari slot 3 bulan ke depan = 3 klik panah + hafalan posisi.

### M6 — Duplikasi halaman

`/dashboard` menampilkan `PatientTherapyCalendar`; `/dashboard/appointments` menampilkan komponen yang sama dengan header berbeda. Tidak ada daftar kronologis sesi, padahal deskripsi halaman menjanjikan "Lihat sesi terapi Anda".

### M7 — Aksesibilitas slide-over

- Panel `role="dialog"` `aria-modal="true"` **tanpa accessible name**.
- Fokus tidak dipindah ke panel saat dibuka (`activeElement` tetap tombol tanggal).
- Escape berfungsi menutup (baik), fokus kembali ke pemicu (baik).

### M8 — Toast menimpa header drawer

Pada 630px, toast sukses/error muncul di atas judul panel dan menutupi tombol tutup (X), termasuk tombol tutup toast sendiri yang terpotong di tepi atas.

### Low

- **L1** Urutan heading: `H1 Dashboard Pasien` → `H3 Rabu, 4 November 2026` (H2 dilompati). Heading "Sesi Akan Segera Berakhir" dari dialog idle juga terbaca.
- **L2** Container dialog idle (`fixed inset-0 z-[100]`, `aria-hidden="true"`, opacity 0) memuat 2 elemen focusable → pelanggaran `aria-hidden-focus`, dan bisa dimasuki Tab.
- **L3** Tombol hamburger header tanpa nama aksesibel (Lighthouse `button-name`).
- **L4** Label tab "Target": `scrollWidth 194 > clientWidth 186`.
- **L5** Istilah status berbeda antar layar (kalender vs kartu appointment vs halaman cetak).
- **L6** Navigasi: "Dashboard / Jadwal / Rekam Medis / Data Saya / Form Awal / Riwayat". Spec `03-DASHBOARD-USER.md` §2: "Ringkasan / Data Saya / Form Awal / Riwayat Terapi / Dokumen / Keamanan Akun". "Keamanan Akun" tidak ada di sidebar.
- **L7** Banner "Belum ada slot tersedia… Silakan hubungi tim Hafta" tidak punya link/aksi.

## 5. Yang sudah baik

- Konfirmasi sebelum masuk mode ubah jadwal jelas: *"Ingin Mengubah Jadwal Sesi Ini?"* + penjelasan apa yang akan terjadi.
- Pesan sukses/gagal spesifik dan manusiawi (bukan kode error), mis. *"Pengajuan ubah jadwal berhasil dikirim. Menunggu konfirmasi (ACC) dari fisioterapis."*
- Banner mode ubah jadwal + tombol **"Batal Ubah"** jelas; warna kuning konsisten dengan makna "tersedia".
- Empty state rekam medis & target menjelaskan kapan data akan muncul.
- Tidak ada error console, tidak ada overflow horizontal, fokus keyboard terlihat (`:focus-visible`), Escape menutup panel, refresh tidak menghilangkan data pengajuan.

## 6. Biaya interaksi (alur ubah jadwal)

Dihitung dari dashboard pasien:

1. Klik tanggal sesi
2. "Ubah Jadwal"
3. "Ya, Pilih Tanggal Baru"
4. Tutup panel (panel full-screen menutupi kalender)
5. Klik tanggal baru
6. (Slot pertama otomatis terpilih)
7. "Ajukan Perubahan Jadwal"

= **7 interaksi**, 2 di antaranya hanya untuk "keluar-masuk panel". Titik keputusan yang membingungkan: langkah 4 (tidak ada instruksi bahwa panel harus ditutup untuk melihat kalender).

## 7. Satu hal yang paling berdampak

**Tampilkan kartu status pengajuan yang persisten** di dashboard & drawer: *"Pengajuan pindah: Rabu, 4 Nov 09:00 → Kamis, 12 Nov 09:00 · Menunggu ACC · [Batalkan]"*.

Ini sekaligus menutup H2, M2, dan sebagian H4 — pasien bisa memverifikasi permintaannya, dan tidak perlu menebak-nebak dari badge di kalender.

## 8. Rekomendasi prioritas

1. **H2 + M2** — kartu/blok status pengajuan (asal → usulan, status, batalkan).
2. **H1** — jalur "ajukan sesi tambahan" atau minimal CTA yang jelas saat punya jadwal aktif.
3. **H3** — konfirmasi eksplisit bila fisioterapis berubah.
4. **H4** — guard UI untuk pengajuan ganda.
5. **M1, M3, M4, M5** — copy, legenda, tap target, navigasi "Hari ini".
6. **M7, L1–L3** — aksesibilitas panel & header (target Lighthouse a11y ≥ 0.95).

## 10. Audit modal, panjang dashboard mobile, dan folder tab (lanjutan)

### 10.1 Modal / pop-up

| # | Severity | Temuan | Perbaikan |
|---|---|---|---|
| MO1 | **High** | Menekan **Ya, Pilih Tanggal Baru** hanya menutup dialog konfirmasi; slide-over tetap menutupi kalender sehingga tanggal kuning tidak terlihat | `confirmReschedule()` kini menutup panel detail (`setIsDateDrawerOpen(false)`) |
| MO2 | **High** | `Escape` saat dialog konfirmasi terbuka menutup **dua** overlay sekaligus (dialog + slide-over) | `Escape` di ConfirmDialog memakai `stopPropagation`; slide-over hanya bereaksi bila `isTopmost` |
| MO3 | Medium | Slide-over `role="dialog"` tanpa accessible name; fokus tidak dipindah ke panel | `aria-labelledby` + fokus otomatis ke panel + focus trap + restore fokus |
| MO4 | Medium | ConfirmDialog tanpa accessible name dan tanpa manajemen fokus | `aria-labelledby`, fokus otomatis, focus trap, restore fokus |
| MO5 | Low | Scroll lock ikut ter-acquire/ release saat overlay baru dibuka di atasnya | Scroll lock dipisah ke effect yang hanya bergantung pada `isOpen` |

Catatan audit: backdrop click, `Escape`, dan scroll lock sudah bekerja; z-index bertingkat (slide-over 41, dialog konfirmasi 42) sudah benar.

### 10.2 Kalender otomatis fokus hari ini

- Sebelumnya tanggal hari ini tidak ditandai sampai pengguna menekan **Hari ini**.
- Sekarang `selectedDate` diinisialisasi ke tanggal hari ini → cincin fokus langsung tampil saat halaman dibuka, dan tombol **Hari ini** mengembalikan bulan + fokus ke hari ini.
- Verifikasi DOM: hanya satu sel ber-`ring-2`, yaitu tanggal hari ini.

### 10.3 Panjang dashboard versi mobile

Baseline: satu halaman scroll **2464 px** (viewport 741 px) tanpa pemisahan bagian.

Solusi: tab bagian khusus mobile (**Jadwal / Catatan / Progres**) — hanya tampil < `lg`; desktop tetap menampilkan grid lengkap.

| Tampilan | Tinggi halaman |
|---|---|
| Sebelum (semua bagian) | 2464 px |
| Tab **Jadwal** | 1522 px |
| Tab **Catatan** | 1270 px |
| Tab **Progres** | 1836 px |

Kartu aksi utama (sesi berikutnya + Form Awal) tetap selalu terlihat di atas tab.

### 10.4 Folder tab sempit

- Grid 3 kolom dipaksa sama lebar → label terasa sesak/terpotong pada layar sempit.
- Diganti menjadi strip tab fleksibel: `flex`, tiap tab `flex-1` dengan lebar minimum 88 px, tinggi 44 px (tap target), label `whitespace-nowrap`, dan strip bisa di-scroll horizontal bila ruang benar-benar sempit (`overflow-x-auto`, scrollbar disembunyikan).
- Ditambah kelengkapan ARIA: `role="tab"`, `aria-controls`, `role="tabpanel"`, `aria-labelledby`, `aria-label` pada tablist.
- Verifikasi: label "Target", "Kehadiran", "Aktivitas" tidak terpotong, tinggi 44 px, panel berganti sesuai tab.

## 13. Perombakan tampilan dashboard pasien (redesign)

Acuan: referensi dashboard kesehatan (bento card, label kecil uppercase, kartu aksen, checklist harian, progress dot) — **palet tetap Hafta** (kuning `--hafta-ylw-*`, charcoal `#181700`, stone, hijau/merah semantik).

### 13.1 Struktur baru

| Area | Isi |
|---|---|
| Header | Chip tanggal, sapaan "Halo, {nama}", ringkasan status (sesi berikutnya / form / pengajuan), aksi utama **Jadwalkan Sesi** + **Form Awal** |
| Bento (4 kartu) | **Sesi Berikutnya** (kartu kuning, CTA lihat jadwal/status), **Form Awal** (status + CTA), **Progres Terapi** (sesi selesai + bar + jumlah terjadwal), **Hari Ini** (checklist 0/2 selesai) |

### 13.2 Perbaikan alur

- Kalender tidak lagi menampilkan judul ganda saat ditanam di dashboard (`hideHeader`).
- Fokus hari ini tetap otomatis (cincin pada tanggal hari ini).
- Progres sesi ditampilkan tanpa klaim klinis baru: hanya status sesi, kehadiran dari sesi tercatat, dan skor nyeri/fungsi yang diisi fisioterapis.

### 13.3 Hasil pengukuran (viewport 741 px)

- Tinggi halaman dashboard: 1522 px → **1341 px** (tab Jadwal), 1306 px (Progres), 858 px (Catatan).
- Tidak ada overflow horizontal; kartu 2×2 pada tablet, 4 kolom pada desktop, scroll-snap pada ponsel.
- Komponen baru: `components/patient/patient-dashboard-cards.tsx` (kartu bento + panel progres + kartu bantuan).
- `PatientDashboardProgressHub` (folder tab) tidak lagi dipakai di dashboard pasien; komponen folder tab tetap dipakai dashboard staf dan tetap diperbaiki (§10.4).

### 13.4 Penyesuaian khusus mobile (revisi)

- **Filter/tab pill dihapus** — semua bagian tampil berurutan (Jadwal → Progres → Catatan); tidak ada lagi kontrol "Jadwal/Progres/Catatan".
- **Kalender full-bleed di ponsel** (`-mx-5`, tanpa radius/border samping) lalu kembali menjadi kartu pada ≥`sm`.
